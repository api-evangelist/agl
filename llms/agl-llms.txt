# AGL Inc. (TIGER GDS)

> AGL Inc. (에이지엘) is a Seoul-headquartered golf technology company founded in 2019 that operates
> TIGER GDS, a global distribution system for golf tee times. Its SaaS platform connects golf club
> inventory to travel and booking channels in real time across more than 1,000 contracted courses
> in 30+ countries, and is the system behind the HeyTeeTime / TIGERBOOKING consumer apps. AGL
> publishes three machine-readable REST contracts on tigergds.com. Offices in Seoul, Tokyo,
> Brea (California) and Singapore.

This file was generated by API Evangelist from AGL's published artifacts on 2026-09-12. AGL does
not publish an llms.txt of its own (HTTP 404/500 on every host probed).

## APIs

- [AGL OTA API](https://api-doc.tigergds.com/reference): Distribution side of TIGER GDS. OpenAPI
  3.1.1, version 2.0, 24 operations. Reference codes, golf club catalogue and detail, tee-time
  open dates and open times, static packages and plan inventory, and the two-phase reservation
  lifecycle. Base URL https://gw-ota.tigergds.com
- [AGL OPEN API](https://api-docs-agl-bridgeapi.tigergds.com/reference): Supplier bridge. OpenAPI
  3.1.1, version 0.0.1, 7 operations in two directions — suppliers register golf clubs, daily tee
  times and availability; AGL calls back with reservation and cancellation requests. Base URL
  https://agl-bridgeapi.tigergds.com
- [AGL Trip.com Reservation Integration API](https://outboundapi-trip-reserv.tigergds.com/swagger/index.html):
  AGL's outbound bridge speaking Trip.com's reservation message format. OpenAPI 3.0.1, one
  operation. Base URL https://outboundapi-trip-reserv.tigergds.com

## How to call these APIs

- AGL OTA API: `Authorization` header token plus an AGL-issued `clientId` header. `language` and
  `currency` are required query parameters on every read.
- AGL OPEN API: `Authorization: Bearer <SHA-256 hashed signature>` plus `X-Supplier-Code`
  (supplier→AGL) or `X-Client-Code` (AGL→supplier). The signing canonicalization is not published.
- Trip.com bridge: JWT bearer plus `ClientId`, `Currency` and `Language` headers, with a signed
  request-header object in the body.

## Things an agent should know before acting

- **HTTP 200 is not success on the OTA API.** It declares only 200 responses; failures arrive as
  `CommonResponse.status == "fail"` with codes `FL00`, `FL01` or `ET00`.
- **No idempotency.** Ten mutating operations, zero replay protection. A retried reservation
  request creates a second hold.
- **Reversal is available and the window is data.** `POST /v2/reservation/request` returns a
  `CancellationPolicy` whose `policies[]` carry `appliesUntil` cut-offs and fee percentages. Read
  them before `POST /v2/reservation/confirm`, which takes payment.
- **Tee times cannot be updated.** AGL's own contract says so: set the existing one unavailable via
  `PUT /api/teetime/availability`, then re-register via `POST /api/teetime/daily`.
- **No sandbox.** The AGL OPEN API declares `https://sandbox-agl-bridgeapi.tigergds.com` but the
  host does not resolve (NXDOMAIN, 2026-09-12).
- **No published rate limits, status page, deprecation policy, changelog, SDK, CLI, MCP server or
  A2A agent card.**
